# 0005. Идентификаторы — UUID v7, генерирует приложение

Статус: принято.

## Контекст

Идентификаторы нужны заказам, позициям меню, корзинам, событиям outbox. Часть из
них приложение обязано знать **до** коммита: `workflow_id` заказа выводится из его
id, событие в outbox ссылается на агрегат, а вставка позиций заказа идёт одной
транзакцией с самим заказом.

## Решение

UUID версии 7, генерирует приложение (`google/uuid`). Расширение `uuid-ossp`
в базу не ставится, `DEFAULT gen_random_uuid()` не используется.

## Последствия

- Идентификатор известен до записи, поэтому вложенные сущности вставляются
  в одной транзакции без `RETURNING` и лишних раундтрипов.
- UUID v7 k-sortable: старшие биты — временная метка. Вставки ложатся в конец
  B-tree индекса, а не размазываются по нему, как у v4. Это снимает главную
  претензию к UUID как первичному ключу.
- Сортировка по id почти совпадает с сортировкой по времени создания. В логах
  это удобно; в бизнес-логике на это никто не опирается — там есть `created_at`.
- Плата — 16 байт против 8 у `bigserial` и отсутствие «короткого» человеческого
  номера. Поэтому у заказа есть **отдельный** человекочитаемый `number`
  (`К-260907-0042`), который называют в поддержке, — id для машин, номер для людей.
- Генерация в приложении означает, что базу нельзя использовать как последнюю
  линию защиты от дублей по id. Уникальность обеспечивается PK, а логическая
  идемпотентность — отдельными ключами (`UNIQUE(user_id, idempotency_key)`).

## Отвергнутые альтернативы

**`bigserial`.** Компактнее и быстрее, но последовательный id раскрывает объёмы
бизнеса наружу и требует раундтрипа за значением перед вставкой связанных строк.

**UUID v4.** Те же 16 байт, но случайные старшие биты: вставки бьют по случайным
страницам индекса, растёт фрагментация и падает локальность кэша.

**`gen_random_uuid()` на стороне базы.** Возвращает id только после вставки —
ровно то, что мешает собрать заказ, его позиции и событие outbox одной транзакцией.

**ULID.** Свойства почти те же, что у UUID v7, но это не тип базы: пришлось бы
хранить строкой или своим доменом. UUID v7 даёт ту же сортируемость нативным `uuid`.
